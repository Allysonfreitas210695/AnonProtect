# Plan 02-03: Gap Closure — SEC-03/SEC-04 Encryption

## Context

A VERIFICATION.md da fase 02 identificou dois requirements orphaned que nenhum dos planos 02-01 ou 02-02 cobriu:

- **SEC-03:** `Message.content` deve ser armazenado com AES-256-GCM
- **SEC-04:** `InvestigationNote.content` deve ser armazenado com AES-256-GCM

O padrão encrypt-on-write + decrypt-on-read já está estabelecido no codebase para `Report.description` e `Report.redactedDescription`. Este plano replica esse padrão para os dois campos faltantes.

**Estado atual confirmado pela VERIFICATION.md:**

- `createMessage()` em `report.data.ts:59` — `content` passado diretamente para `prisma.message.create` sem `encrypt()`
- `createAdminReply()` em `admin.data.ts:35` — `content` passado diretamente para `prisma.message.create` sem `encrypt()`
- `createInvestigationNote()` em `admin.data.ts:54` — `content` passado diretamente para `prisma.investigationNote.create` sem `encrypt()`
- `getReportByCode()` em `report.query.ts` — messages retornadas sem decrypt loop
- `getReportById()` em `admin.query.ts` — messages e investigationNotes retornadas sem decrypt loop

**Infraestrutura disponível:**

- `encrypt` já está importado em `report.data.ts` (linha 5) mas não usado em `createMessage()`
- `decrypt` já está importado em ambos os query files
- Mock de crypto já existe em `report.data.test.ts`: `encrypt: vi.fn((text) => \`encrypted\_\${text}\`)`

### Task 2 — decrypt messages em getReportByCode() [report.query.ts]

**Arquivo:** `src/_modules/report/report.query.ts`

`decrypt` já está importado (linha 4). Adicionar loop de decrypt após construir o retorno em `getReportByCode()`. O padrão existente (linhas 31-41) decripta apenas `report.description`. Estender para decriptar cada `message.content`:

```typescript
// ANTES (linha 38-41):
return {
  ...report,
  description: decryptedDescription,
}

// DEPOIS:
const decryptedMessages = report.messages.map((msg) => {
  let content = msg.content
  try {
    content = decrypt(msg.content)
  } catch {
    // content permanece ciphertext se decrypt falhar (dado legado ou corrompido)
  }
  return { ...msg, content }
})

return {
  ...report,
  description: decryptedDescription,
  messages: decryptedMessages,
}
```

## Risk Assessment

**Risco:** Dados existentes no banco foram armazenados em plaintext. Decrypt de plaintext vai falhar (não é ciphertext válido).
**Mitigação:** Os loops de decrypt usam `try/catch` e fazem fallback para o valor original — o mesmo padrão já em uso para `Report.description`. Sem risco de quebra em dados legados.

**Risco:** Testes existentes quebram.
**Mitigação:** Task 4 identifica exatamente o único teste afetado (`createMessage` em `report.data.test.ts`) e especifica a correção.
