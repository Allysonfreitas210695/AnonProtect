<task type="auto">
  <name>Task 2: Replace isVisible-guard tests with real assertions and swap fixed timeouts for condition waits</name>
  <files>e2e/auth.spec.ts, e2e/admin-reports.spec.ts, e2e/admin-settings.spec.ts, e2e/report.spec.ts</files>
  <action>
Fix the silent-pass tests. For each, replace the `if (await x.isVisible()) { ...only assertion... }` pattern with a real assertion when the element is expected given seeded data:

- admin-reports.spec.ts test 03 (search filter): the search input is expected on the reports list page — replace the guard with `await expect(searchInput).toBeVisible({ timeout: 10000 })`, then fill/press Enter, then assert the table is still visible (`await expect(page.locator('table')).toBeVisible()`) instead of the throwaway `expect(body).toBeVisible()`.
- admin-reports.spec.ts test 05 (view detail from dashboard): assert `await expect(detailsLink).toBeVisible({ timeout: 10000 })` (seed guarantees at least one report), click, waitForURL for the detail route, then assert a detail-page element visible instead of body.
- admin-reports.spec.ts test 06 (status dropdown): same — assert detailsLink visible, navigate, then `await expect(statusSelect).toBeVisible()` and assert its value is truthy. Remove the nested guards.
- admin-settings.spec.ts test 04 (profile personal info form): the name input is expected on the profile form — replace guard with `await expect(nameInput).toBeVisible({ timeout: 10000 })` then `await expect(nameInput).toHaveValue(/administrador/i)`.
- auth.spec.ts test 07 (forgot-password submission): the submit button and email input are expected on the forgot-password page — assert `await expect(submitBtn).toBeVisible()` and `await expect(emailInput).toBeVisible()`, fill and click, then assert a post-submit signal (page still renders / confirmation text) rather than the body-only check. If no reliable confirmation text exists, keep `await expect(page.locator('body')).toBeVisible()` after asserting the form elements were present.
- report.spec.ts test 03 (track valid code): the tracking input is expected — assert `await expect(input).toBeVisible()`, fill code, click track button (assert button visible first), then wait for the status result via a condition-based wait instead of `waitForTimeout(3000)` — e.g. `await expect(page.getByText(/status|situação|em análise|recebid/i).first()).toBeVisible({ timeout: 10000 })`; if no deterministic status text is guaranteed, fall back to `await page.waitForLoadState('networkidle')` then assert body.

Only keep a genuine conditional where element presence is legitimately optional business logic — none of the above cases qualify given seeded data, so all should become hard assertions.

Then reduce fixed `waitForTimeout` calls across these four files: after navigation/clicks that are followed by an `expect(...).toBeVisible()` or `toHaveText()`, delete the preceding `waitForTimeout` (Playwright expect auto-retries/polls). For URL-change assertions use the existing `waitForURL`. Keep a `waitForTimeout` ONLY where there is no observable DOM signal — e.g. auth.spec.ts test 08 and admin-settings tests 05/08 assert on `page.url()` after a redirect that has no element to await; there prefer `await page.waitForURL(/pattern/)` if the target URL is known, otherwise keep a single short timeout. Do not remove the redirect settle waits blindly if they guard `page.url()` checks with no locator to await.

Do not change which scenarios run or their describe/test names. Preserve prettier style.
