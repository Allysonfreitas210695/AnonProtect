<objective>
Close review findings WR-01 (no rate limiting on the unauthenticated `sendMessageAction`) and WR-02 (no write-side backpressure on the now-uncapped admin message read) from 03-REVIEW.md.

The SES email wiring (CHAT-07) plus the removed `take: 50` cap (CHAT-04) created a cost/DoS surface: an unauthenticated actor who knows a `reportId`/`code` pair can grow a thread unboundedly, each write triggering a live SES send and inflating the admin detail-page read. This plan bounds both the _rate_ (per-IP limiter) and the _total_ (per-report hard cap) of message writes.

Purpose: Prevent SES cost/quota abuse and unbounded thread growth without adding pagination (D-01 keeps fetch-all).
Output: A dedicated message rate limiter, a per-report message ceiling enforced before write, and tests proving both gates.
</objective>
