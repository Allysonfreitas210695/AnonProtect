  <action>
In `getReportStats`, remove the `prisma.report.findMany({ where, select: { createdAt: true }, orderBy: { createdAt: 'asc' } })` call from the `Promise.all` array (the `reports` binding) AND the trailing `timelineMap`/`reports.forEach` block that builds `timelineData` (currently ~lines 319-328).

Replace with a `prisma.$queryRaw` call inside the same `Promise.all`, bound to a new `rawTimeline` variable typed `{ day: Date; count: bigint }[]`. Build the query with `Prisma.sql` (Prisma is already imported from `@/_generated/prisma`) so the dynamic filters are parameterized bound values — NEVER interpolate `filterCountry` or `startDate` into the SQL string.

Construct conditional WHERE fragments: start with `Prisma.sql\`deleted_at IS NULL\``; if `startDate`is set, AND`created_at >= ${startDate}`; if `filterCountry`is set, AND`country = ${filterCountry}`. Compose them, e.g. build an array of `Prisma.sql`conditions and join with`Prisma.join(conditions, ' AND ')`, then embed via `WHERE ${whereClause}`. The final query mirrors getPublicStats: `SELECT date_trunc('day', created_at) as day, count(\*)::bigint as count FROM reports WHERE ${whereClause} GROUP BY day ORDER BY day ASC`.

Map the raw result to the existing shape: `const timelineData = rawTimeline.map((r) => ({ date: r.day.toISOString().split('T')[0], count: Number(r.count) }))`. This preserves the current `YYYY-MM-DD` UTC-formatted `date` string and numeric `count` produced by the old `createdAt.toISOString().split('T')[0]` bucketing. Keep `resolutionData` findMany and all other groupBy calls untouched. `avgResolutionTime`, statusStats, categoryStats, departmentStats, countryStats, cityStats, and the final return object stay identical.
