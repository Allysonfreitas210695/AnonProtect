# Quick Task 261111-p2a: Prioridade 2 — ajustes pequenos de código

Itens de código da Prioridade 2 do relatório de correções. 2.6 (proteção de branch no GitHub)
e 2.7 (medição de cobertura/acessibilidade) não são mudanças de código e ficam fora.

## Tarefas

1. **2.1 Pré-filtro determinístico** — `src/_shared/lib/pii-filter.ts`: regex para e-mail,
   CNPJ, CPF, CEP e telefone, trocando por `[DADO PROTEGIDO]`. Aplicado em `analyzeReport`
   antes do envio ao Gemini e nas mensagens do usuário em `getChatCompletion`. Testes
   unitários em `pii-filter.test.ts`.
2. **2.2 Endurecer `analyzeReport`** — instruções em `systemInstruction`, relato entre
   `<relato>…</relato>` com instrução de tratá-lo como dado (tags internas neutralizadas);
   `temperature: 0`; Zod (enum de prioridade, já existente); checagem de que o texto redigido,
   sem as marcas, só contém trechos do original pré-filtrado, na ordem. Se falhar, retorna
   `null` → denúncia fica em "Aguardando anonimização" (fluxo já existente, com retry).
3. **2.3 activity_logs** — `onDelete: Restrict` na relação `ActivityLog.report` + migration
   `ALTER TABLE` da FK. Sem hard delete de denúncias no código (só soft delete), então nada
   quebra.
4. **2.4 `after()`** — conferido: `triggerAiAnalysis` já usa `after()` de `next/server`.
5. **2.5 Server Actions** — todas as actions admin usam `adminActionClient` /
   `supervisorActionClient` / `authActionClient` ou chamam `getCurrentUser()`. Achado:
   `src/_actions/public/ai-analysis.ts` tem `'use server'`, o que expõe `triggerAiAnalysis`
   como endpoint público sem autenticação (permitiria sobrescrever o texto redigido de uma
   denúncia conhecendo o UUID). Correção: trocar `'use server'` por `import 'server-only'`.
   Teste de regressão RBAC para as actions admin.
6. **2.8 Turnstile** — no envio, se o widget estiver ativo e não houver token, bloquear no
   cliente com mensagem visível (inline + toast); limpar token em erro/expiração do widget e
   resetar após falha do servidor. Chaves i18n nos 3 idiomas.
