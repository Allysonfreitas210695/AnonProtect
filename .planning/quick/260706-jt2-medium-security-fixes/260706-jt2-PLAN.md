<objective>
Fix three medium-severity security findings from the AnonProtect code audit:

1. Missing authorization check in `deleteInvestigationNote` — any SUPERVISOR can currently delete any other user's investigation note.
2. `attachments[].url` in `reportSchema` accepts any external domain — phishing vector when rendered in the admin evidence gallery.
3. Credentials login has no rate limiting — brute-force surface on `loginAction`.

Purpose: Close authorization, injection/phishing, and brute-force gaps identified in the prior security audit, following exactly the same patterns already established for `checkUploadRateLimit` (rate limiting) and existing error-handling conventions.

Output: Updated `admin.data.ts` (authorship+role check), `report.action.ts` (passes role through), `report.ts` schema (domain-restricted attachment URL) + `aws.ts` (exported hostname helper), `ratelimit.ts` (new `checkLoginRateLimit`), `login.action.ts` (rate limit gate). Updated/added tests for all of the above.
</objective>
