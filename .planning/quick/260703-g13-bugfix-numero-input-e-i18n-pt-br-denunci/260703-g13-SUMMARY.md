# Phase quick-260703-g13 Plan 01: Fix número input freeze + missing pt-BR i18n keys Summary

Stabilized the CEP-lookup `useEffect`/`handleCepLookup` reference chain to stop a render loop that froze form inputs, and added the missing `NewReport.uploading`/`NewReport.analyzing` translation keys to all three locale files.

## What Was Done

**Task 1 — Campo "número" travando (loop de re-render via CEP lookup)**

- `src/_hooks/public/use-cep-lookup.ts`: wrapped `handleCepLookup` in `useCallback(..., [form])`. Since react-hook-form's `useForm()` returns a stable `form` object across renders, the callback reference is now stable too.
- `src/app/[locale]/(auth)/report/new/_components/form.tsx`: removed `form` from the CEP-lookup `useEffect` dependency array (kept `postalCode`, `isBrazil`, `handleCepLookup`). Added an eslint-disable comment for `exhaustive-deps` since `form` is intentionally excluded (stable ref, not needed for effect re-execution logic).
- Did not touch the `Input` for `name="number"` — it remains fully controlled via `{...field}`, no manual `value`/`onChange` introduced.
- Left the other two `useEffect`s in `form.tsx` (locale-lock and no-number checkbox) untouched — they were not implicated by the plan's root-cause analysis and are out of scope.

**Task 2 — Chaves i18n ausentes**

- Added to `NewReport` namespace in all three message files, directly after `submitting`:
  - pt-BR: `"uploading": "Enviando anexos..."`, `"analyzing": "Analisando denúncia..."`
  - en: `"uploading": "Uploading attachments..."`, `"analyzing": "Analyzing report..."`
  - es: `"uploading": "Subiendo archivos..."`, `"analyzing": "Analizando denuncia..."`
- `submit`/`submitting` keys left untouched.
