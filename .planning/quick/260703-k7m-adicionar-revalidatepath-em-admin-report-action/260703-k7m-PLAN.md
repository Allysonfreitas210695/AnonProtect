<objective>
Bug descoberto durante teste manual E2E completo (Playwright) do painel admin: nenhuma das server actions em `src/_actions/admin/report.action.ts` (updateReportStatusAction, sendAdminReplyAction, createInvestigationNoteAction, deleteInvestigationNoteAction, forwardReportAction, batchUpdateReportStatusAction, deleteReportAction) chamava `revalidatePath`, ao contrário do padrão já usado em `src/_actions/public/message.action.ts` e `src/_actions/admin/category.action.ts`.

Efeito observado: ao mudar o status de uma denúncia, adicionar nota de investigação ou responder ao denunciante, a UI (badge de status no cabeçalho, contador de notas, lista de mensagens) não atualizava até um reload manual da página — mesmo com a mutação persistida corretamente no banco. Isso é confuso para o operador do painel (parece que a ação falhou silenciosamente).

Causa raiz: a página `/admin/report/[id]` é um Server Component que busca os dados via `admin.query.ts`; sem `revalidatePath`, o Next.js Router Cache serve o payload RSC antigo após a navegação client-side disparada pelas actions.

Output: `revalidatePath` adicionado após cada mutação, invalidando `/admin/report/[id]` (e `/admin/report` + `/admin` quando a ação afeta a lista/dashboard).
</objective>
